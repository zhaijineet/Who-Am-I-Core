# Creative Content Designer 记忆

## 项目特征

### Who Am I Core 模组
- **类型**: Minecraft NeoForge 模组
- **基础**: 基于 Chest Cavity Beyond 扩展
- **核心玩法**: 器官系统，玩家可以在胸腔(3x9网格)中装备不同器官
- **器官类型**: 龙类器官(火/冰/电)、悚恐怖官、九头蛇、幻想种、墨水/颜料、弗兰肯斯坦、肿瘤、木质、拟态等
- **技术栈**: Java, NeoForge, OrganBuilder系统

### 已实现器官系统特性
- 器官使用 OrganBuilder 构建器模式创建
- 器官有属性系统(HEALTH, SPEED, STRENGTH等)
- 器官有技能系统(organSkillConsumer)
- 器官有事件系统(chestCavityOpen/Close, tick, attack等)
- 已实现相邻位置计算逻辑(getAdjacentSlots方法)
- 胸腔为3x9网格，共27个槽位（0-26索引）
- ChestCavityData继承ItemStackHandler，提供固定槽位访问
- 关键API: getStackInSlot(int), getOrganCount(Item), hasOrgan(Item)

## 成功设计模式

### 器官搭配体系设计 v1.0 (2026-03-15 初版)

**设计成果**:
- 完整的器官搭配系统设计文档 (`docs/design/organ-synergy-system.md`)
- 搭配速查表 (`docs/design/synergy-quick-reference.md`)

**核心设计理念**:
1. **易学难精**: 多层级效果，从入门到传说
2. **多样性**: 12种主要协同类型，数百种搭配组合
3. **主题性**: 搭配效果与器官背景故事相符
4. **平衡性**: 效果强度分级，稀有度匹配
5. **可扩展性**: 模块化设计，易于添加新内容

**五大搭配类型**:
1. 相邻触发 (Adjacent Synergy) - 器官在网格中相邻
2. 套装触发 (Set Bonus) - 装备指定数量同类器官
3. 主题触发 (Thematic Synergy) - 跨器官类型的主题组合
4. 对立触发 (Opposition Synergy) - 对立属性的和谐
5. 几何触发 (Geometric Synergy) - 形成特定几何图案

**v1.0 技术问题**:
- ❌ 几何搭配技术实现难度过高
- ❌ 九狱顺序检测不可行（ItemStackHandler没有装备顺序）
- ❌ 拟态器官机制不明确（"模仿任何器官"太抽象）
- ❌ 幻想种效果无法实现（"修改游戏规则"超出API能力）
- ⚠️ 缺少具体性能优化方案

## 记录的设计模式

### 器官搭配设计模式

#### 相邻触发模式
```java
// 条件: 器官在胸腔网格中相邻
// 效果: 中等增益
// 示例: 火龙心脏 + 火龙肺脏 → +15%火焰伤害
```

#### 套装触发模式
```java
// 条件: 装备N个同类器官
// 分级: 2件/4件/6件/8件
// 效果: 随数量递增
// 示例: 火龙4件 → +20%火焰伤害 + 技能
```

#### 主题触发模式
```java
// 条件: 跨器官类型的主题组合
// 无需相邻
// 示例: 火/冰/电龙各2个 → 三龙共鸣
```

#### 效果强度分级
```
★☆☆☆☆ 入门级: +5-15% 属性
★★☆☆☆ 进阶级: +15-30% 属性
★★★☆☆ 专家级: +30-50% 属性
★★★★☆ 大师级: +50-80% 属性
★★★★★ 传说级: +80-100% 属性
```

- 完整的类型差异化机制
- 分类标签系统和套餐设计
- 视觉与特效差异化设计
- 获取方式差异化设计

**三种类型特征**:

#### 良性肿瘤 (3个)
**主题**: 适应 - 肿瘤与身体的和谐共存
**器官**: 肿瘤胃、肿瘤肺脏、肿瘤脾脏
**特征**: 高稳定性(95%+)、低风险(★★☆☆☆)、中等收益(★★★☆☆)
**套餐**:
- 2件: 副作用持续时间-25%
- 3件: 完美适应(每10秒恢复5%生命,积累适应层数)

#### 恶性肿瘤 (4个)
**主题**: 侵蚀 - 肿瘤对身体的侵蚀和变异
**器官**: 肿瘤心脏、肿瘤肌肉、肿瘤肝脏、肿瘤肾脏
**特征**: 低稳定性(50-70%)、高风险(★★★★☆)、高收益(★★★★★)
**套餐**:
- 2件: 随机副作用概率-5%,收益+10%
- 3件: 侵蚀之主(造成伤害积累侵蚀层数)
- 4件: 肿瘤军团(层数上限+5,清除速度翻倍)

#### 特殊肿瘤 (2个)
**主题**: 突变 - 肿瘤的极端变异和进化
**器官**: 肿瘤阑尾、肿瘤肠子
**特征**: 极端稳定性(0-100%)、极高风险(★★★★★★)、极端收益
**套餐**:
- 2件: 突变共鸣(触发提升10%,可预测结果)

**视觉差异化**:
- 良性: 暗紫色 + 深红色,柔和脉动
- 恶性: 病态绿色 + 鲜红色,剧烈波动
- 特殊: 彩虹色渐变,不规则特效

**技术实现**:
- 标签系统: BENIGN_TUMOR, MALIGNANT_TUMOR, SPECIAL_TUMOR
- 类型统计: getBenignTumorCount(), getMalignantTumorCount(), getSpecialTumorCount()
- 套餐检测: 基于类型数量的套餐效果
- 性能优化: 缓存机制,延迟计算

**T3/T4兼容性**:
- T3增殖: 良性稳定增殖,恶性危险增殖,特殊随机增殖
- T4共生: 同类型共生(良性-良性,恶性-恶性,特殊-特殊),跨类型共生

### 设计模式总结

#### 肿瘤器官设计模式

**核心设计公式**:
```
肿瘤器官 = 高基础属性 + 独特机制 + 相应代价 + 增殖主题
```

**分类依据**:
1. **稳定性**: 随机性低且效果可预测 → 良性
2. **风险收益比**: 高风险高收益且随机性强 → 恶性
3. **机制独特性**: 改变游戏规则或完全随机 → 特殊

**套餐设计模式**:
- **2件**: 小幅优化(副作用减少或小幅增强)
- **3件**: 主题强化(获得独特能力,如适应光环、侵蚀之主)
- **4件**: 系统强化(层数系统增强,如肿瘤军团)

## 肿瘤派系简化设计 (2026-03-15)

### 简化背景

原设计问题(T1-T7):
- ❌ 系统层次过多(6层: T1-T7)
- ❌ 每个器官都有多重复杂效果
- ❌ 增殖机制、共生机制过于复杂
- ❌ 层数系统太多(毒素积累、废物堆积、适应层数等)
- ❌ 类型分类(良性、恶性、特殊)套餐效果复杂

### 简化设计成果 v2.0 (技术可行性修正)

**设计文档**: `docs/design/tumor-simplified-faction-design.md`

**核心决策**:
1. ✅ **统一核心机制**: 侵蚀层数系统(类似冰火的温度系统)
   - 装备肿瘤器官=积累侵蚀层数
   - 层数越高越强,但生命流失越快
   - 4个阶段: 适应期(0-2层)、活跃期(3-5层)、危险期(6-8层)、极限期(9-10层)

2. ✅ **简化器官列表**: 从9个减少到6个核心器官
   - 保留: 心脏(核心)、肌肉(伤害)、肝脏(药水)、肺脏(持续伤害)、脾脏(防御)、阑尾(特殊)
   - 删除: 胃(功能简单)、肠子(状态循环复杂)、肾脏(与肝脏重复)

3. ✅ **删除冗余系统**:
   - 移除增殖机制(T3)
   - 移除共生机制(T4)
   - 移除类型分类(T2的良/恶/特殊)
   - 移除多重层数系统,只保留侵蚀层数

4. ✅ **简化搭配规则**:
   - 套装搭配: 基于器官数量(2/4/6个)
   - 相邻搭配: 简单的相邻触发(心+肌,肺+肝,脾+阑尾)
   - 特殊搭配: 全套6个=临终爆发(修订)

### v2.0 修订内容 (解决审核问题)

**严重问题 (必须解决)**:
1. ✅ **数据持久化**: 扩展 ChestCavityData,利用现有 Attachment 系统
2. ✅ **层数计算**: 事件驱动+脏标记+延迟计算机制
3. ✅ **肝脏简化**: 删除毒素层数系统,改为基于侵蚀层数的阈值效果

**建议问题 (选择性解决)**:
4. ✅ **阑尾调整**: 70/30概率,增加可重试机制(30秒冷却)
5. ✅ **6件套平衡**: 从"不死之身"改为"临终爆发"(10秒无敌后恢复1点生命)
6. ✅ **层数上限**: 删除15层设计,固定10层上限
7. ✅ **UI集成**: 提供扩展胸腔UI和使用经验条两种方案
8. ✅ **肌肉痉挛**: 简化为伤害触发+5秒冷却
9. ✅ **脾脏免疫**: 添加30秒冷却
10. ✅ **粒子效果**: 距离剔除(16格)和频率限制
11. ✅ **器官难度**: 调整阑尾为4星难度

### 技术实现要点

**数据持久化**:
- 在 ChestCavityData 中添加肿瘤专属字段
- 利用 NeoForge Attachment 系统自动序列化
- 无需额外网络包,复用胸腔同步机制

**事件驱动机制**:
- 器官变化时标记脏(erosionStacksDirty)
- 胸腔关闭时统一计算更新
- 玩家登录时初始化一次

**性能优化**:
- 脏标记避免频繁计算
- 缓存当前层数和套装状态
- 批量更新效果
- 粒子效果距离剔除

**UI集成方案**:
- 方案1: 扩展胸腔UI顶部显示侵蚀层数
- 方案2: 使用经验条显示侵蚀层数进度

### 核心机制: 侵蚀层数系统

**与冰火温度系统的对比**:
| 特征 | 冰火-温度 | 肿瘤-侵蚀层数 |
|------|----------|-------------|
| 核心机制 | 全局+局部温度 | 统一层数系统 |
| 获取方式 | 器官影响温度 | 器官数量=层数 |
| 效果类型 | 3种状态 | 4个阶段 |
| 风险机制 | 极端温度惩罚 | 高层数生命流失 |
| 控制方式 | 装备不同器官 | 装备/卸载器官 |
| 数据持久化 | Attachment | Attachment(扩展ChestCavityData) |
| 事件驱动 | ✓ | ✓ |

**侵蚀层数效果**:
- 0-2层(适应期): +5%所有属性,无代价
- 3-5层(活跃期): +15%所有属性,+10%伤害,每5秒失1点生命
- 6-8层(危险期): +30%所有属性,+25%伤害,每3秒失2点生命
- 9-10层(极限期): +50%所有属性,+50%伤害,每秒失3点生命,无法自然恢复

### 设计优势

1. **易学难精**: 简单的层数系统,但层数控制需要策略
2. **清晰直观**: 层数=强度=风险,一目了然
3. **技术可行**: 所有效果都可以通过现有API实现
4. **平衡良好**: 低中高风险层次分明
5. **主题鲜明**: 肿瘤的"侵蚀"主题贯穿始终
6. **性能优化**: 事件驱动+缓存机制,性能影响最小化

### 与冰火派系的定位

- **冰火派系**: 温度平衡策略,适合精细管理型玩家
- **肿瘤派系**: 风险回报博弈,适合追求极限的玩家

两个派系提供不同游戏体验,丰富游戏内容。
